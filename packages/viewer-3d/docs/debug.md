# Debug HUD 설계 개요

엔진에서 방출하는 고정 포맷 디버그 로그를 그대로 시각화하기 위해 `viewer-3d` 패키지에 HUD를 구성했다. HUD는 결정론을 유지하면서 가벼운 오버헤드로 GAP→ActEval→Commit→Fire/Abort 파이프라인을 추적할 수 있도록 데이터 경로와 UI를 분리해 설계했다.

## 데이터 파이프라인

- **전송 훅**: 엔진은 `dbg::emit_line()`을 통해 한 줄 문자열을 `window.__FTO_DBG(line)`에 밀어 넣는다. 훅이 없을 때는 `console.log`로 폴백한다.
- **파서 (`debug/parser.ts`)**: 태그(예: `G`, `E`, `C`…), `t=틱`, `p=pid` 등의 필드만 정규식 한 번으로 추출하고, 숫자는 즉시 `number`로 강제 변환한다. 기타 키=값 페어는 `fields`에 저장한다.
- **스토어 (`debug/store.ts`)**: 이벤트를 링버퍼(최대 8192)와 `Map<tick, TickBucket>`, `Map<pid, PlayerDebugBucket>`에 삽입한다. 태그 비트마스크로 가시성을 제어하고, 구독자에게 `event`/`mask` 업데이트를 발행한다.
  - `snapshot(tick, pid?)`은 HUD 패널들이 공통으로 사용하는 결정적 조회 API다.
  - `getRecentEvents(limit)`은 콘솔 패널용 가상 스크롤 데이터 공급원이다.
- **타임라인 결정론**: HUD 갱신은 `K`(tick) 태그를 받은 시점에만 재계산한다. 스크럽 중에는 추가 로그 없이 스냅샷 데이터를 조회한다.

## 화면 레이아웃

HUD 루트는 오버레이 전용 `<div>`이며, 내부는 다음 패널로 구성된다.

| 영역 | 설명 |
| --- | --- |
| **상단 글로벌 바** | 현재 틱·시뮬레이션 시간·포커스 선수·볼 보유 선수·전술 프리셋·FPS를 표시한다. 재생/스텝(±1/±10), AI 전용 스텝, Physics 전용 스텝 버튼과 태그 체크박스 필터가 포함된다. |
| **좌측 타임라인** | 20Hz 틱 슬라이더와 이벤트 마커 목록. G/E/C/F/X/W/R 태그별 아이콘을 사용하며, 마커 클릭 시 해당 이벤트에 포커스를 이동한다. |
| **중앙 피치 캔버스** | 2D 오버레이 캔버스 한 장으로 GAP 미니바, Commit 아우라, ActEval 화살표(최상위 3개, 점선), Fire 궤적 하이라이트, Wait 카운트다운 링을 갱신한다. |
| **우측 인스펙터** | 선수 패널(헤더+GAP 바+패스 옵션 테이블), ActEval 리스트, 필터 사유 뱃지, 이벤트 상세 패널을 묶는다. |
| **하단 콘솔** | 최근 로그를 역순 테이블로 표시한다. `pid`, `tag`, `tick 범위` 필터와 RAW 문자열 툴팁을 제공한다. |

모든 패널은 `pointer-events: auto`, 3D 렌더링 영역은 `pointer-events: none`으로 설정해 HUD 위에서만 상호작용하도록 구성했다.

## 인터랙션/핫키

- **재생 제어**: Space(토글), ←/→(±1틱), Shift+←/→(±10틱)을 HUD 버튼과 동기화했다.
- **태그 필터**: 숫자 키 1~9는 대응 태그를 토글, 0은 전부 on/off 전환.
- **포커스 연동**: 타임라인/콘솔에서 마커를 클릭하면 해당 틱과 선수로 인스펙터가 동기화된다. HUD가 최신 틱을 추적 중일 경우 새로운 로그가 들어오면 자동으로 최신 상태를 따라간다.
- **캔버스 Hover/Alt**: ActEval 리스트 항목 Hover 시 오버레이 화살표가 강조되도록 스타일 클래스를 부여했다. (세부 구현은 HUD 오버레이와 연동해 확장 가능)

## 성능 메모

- **파싱 비용**: 정규식은 사전 컴파일하지 않아도 10µs 목표를 충족하며, 해당 값이 문제 되면 `RegExp` 재사용으로 최적화할 수 있다.
- **렌더링**: 오버레이는 매 프레임 전체를 지우고 다시 그리지만, 20Hz 입력 기준 변동량이 작아 GPU 부담이 낮다. 필요 시 OffscreenCanvas로 옮겨 워커 렌더링을 적용할 수 있도록 함수 분리해 두었다.
- **메모리**: 이벤트당 약 120B 추산 → 링버퍼 8k 유지 시 1MB 미만. 객체 풀을 통해 GC 압력을 줄일 수 있도록 구조체를 유지하고 있다.

## 적용 포인트

- 뷰어 초기화 시 `import './debug'`를 통해 `window.__FTO_DBG` 훅이 생성되며, HUD 인스턴스는 `debugStore`를 직접 받아 구독하도록 설계했다.
- HUD의 `renderOverlay(camera, renderer)`는 메인 렌더 루프 후 호출해야 하며, 기존 3D 씬을 건드리지 않는다.
- HUD 콜백(`requestStep`, `requestTick`, `requestPlayerFocus` 등)을 `ViewerApp`이 주입해 엔진 재생/정지 상태와 동기화한다.

## 향후 개선 아이디어

- AI 전용/Physics 전용 스텝 버튼은 현재 전체 틱을 대체 실행하고 경고를 남긴다. 엔진이 해당 서브스텝 API를 제공하면 바로 연동 가능하도록 인터페이스만 분리해 뒀다.
- 과거 틱으로 스크럽 시 실제 시뮬레이션 상태는 최신 프레임을 유지한다. `SimView` 스냅샷을 저장하면 HUD와 피치 오버레이를 과거 상태로 재구성할 수 있다.
- Wait 이벤트 링에 잔여 ms 외에 게이트 상태(열림/닫힘)를 색상으로 표현하면 가독성이 올라간다.

이 문서는 HUD 전반 구조와 데이터 흐름을 파악하려는 구현 담당자를 위한 개요이며, 세부 UI 구조는 `src/scene/hud.ts`와 `src/styles.css`를 참고하면 된다.
