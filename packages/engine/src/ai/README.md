# AI 아키텍처 개요

이 문서는 FTO 축구 시뮬레이션 엔진의 AI 아키텍처를 설명합니다. AI는 각 선수의 두뇌 역할을 하는 **유한 상태 기계(FSM)**를 중심으로, 여러 모듈이 유기적으로 결합된 컴포넌트 기반 접근 방식을 따릅니다.

## 모듈 설명

### `fsm.rs` - 두뇌 (Finite State Machine)

*   **역할:** AI 의사결정의 최상위 계층으로, 각 선수의 "두뇌" 역할을 합니다. 경기 상황에 따라 선수가 어떤 **"상태"** 또는 **"의도"** 를 가질지 결정합니다. (예: '공격 가담', '공을 쫓음', '수비 위치로 복귀')
*   **흐름:** `perception`(인지), `utility`(판단) 같은 다른 모듈을 사용하여 상황을 평가하고, 자신의 상태를 결정합니다. 예를 들어, 팀이 공격 상황이고 자신이 공을 가지고 있다면 `OnTheBall` 상태로 전환합니다.
*   **핵심:** `tick()` 함수가 AI 로직의 시작점이며, `PlayerClass`에 의해 각 선수마다 주기적으로 호출됩니다.

### `utility.rs` - 전략가 (Utility System)

*   **역할:** 특정 상황에서 가능한 여러 행동들의 "효용성(Utility)"을 점수화하여, FSM이 더 현명한 결정을 내리도록 돕는 함수들의 모음입니다. "지금 당장 할 수 있는 최선의 행동은 무엇인가?"라는 질문에 답합니다.
*   **예시:** `OnTheBall` 상태일 때, '슈팅', '안전한 짧은 패스', '위험하지만 결정적인 스루 패스' 등의 행동들의 점수를 각각 계산하고 가장 점수가 높은 행동을 선택하게 할 수 있습니다.
*   **현재 상태:** 현재는 이 로직의 일부가 `on_the_ball_action.rs` 안에 `score_shoot`, `score_pass` 등으로 구현되어 있습니다. 향후 이 모듈로 중앙화할 수 있습니다.

### `perception.rs` - 눈 (Perception System)

*   **역할:** 선수의 관점에서 게임 세계의 정보를 수집하고 해석하는 "눈과 귀"의 역할을 합니다.
*   **기능:** 원본 `World` 상태를 입력받아, "팀 동료는 어디에 있는가?", "가장 가까운 상대는 누구인가?", "골대까지의 거리는?" 등 AI가 의사결정을 내리는 데 필요한 정보들을 가공하여 `Perception` 구조체에 담아 제공합니다.

### `scheduler.rs` - 지휘자 (AI Scheduler)

*   **역할:** 성능 최적화를 담당하는 모듈입니다. AI의 의사결정 자체가 아닌, **"언제 AI가 생각할 것인가"**를 결정합니다.
*   **기능:** 22명 전체의 복잡한 AI 연산을 매 프레임마다 실행하는 것은 비용이 매우 큽니다. 스케줄러는 이 연산 주기를 분산시켜, 게임의 전반적인 성능을 유지하면서도 AI가 반응성을 잃지 않도록 조절합니다.

### `actions/` - 팔다리 (Action Handlers)

*   **역할:** FSM과 Utility 시스템이 결정한 최종 행동을 실제로 수행하는 "팔다리" 역할을 합니다.
*   **예시:**
    *   `pass_action.rs`: 특정 대상에게 패스를 실행합니다.
    *   `shoot_action.rs`: 골대를 향해 슈팅을 실행합니다.
    *   `defensive_action.rs`: 압박, 대인 마크 등 수비 동작을 수행합니다.
*   **흐름:** FSM에 의해 행동이 시작(`begin`)되고, 정해진 시간 동안 또는 특정 조건이 만족될 때까지 매 틱마다 `update`가 호출되며, 행동이 끝나면 `is_done`이 true를 반환합니다.

## 향후 개발 아이디어

1.  **`fsm.rs`에 전술 시스템 완벽 연동:**
    *   `fsm.rs`의 `decide` 함수가 전술을 AI에 반영하는 핵심 장소가 되어야 합니다.
    *   **팀 전술:** `player_class.quantified_tactics` (예: `press_intensity`) 값을 사용하여 상태 전환을 결정합니다. 압박 강도가 높으면 '대기' 상태보다 '압박' 상태를 더 선호하게 만듭니다.
    *   **개인 지침:** `player_class.personal_instructions` (예: `risk_intensity`) 값을 사용하여 같은 역할의 선수라도 개인마다 다른 성향의 플레이를 하도록 만듭니다.

2.  **`utility.rs`에 판단 로직 중앙화:**
    *   `on_the_ball_action.rs`에 흩어져 있는 점수 계산 로직(`score_shoot` 등)을 `utility.rs`로 옮겨와 중앙에서 관리합니다.
    *   패스, 슈팅, 드리블 등 더 다양한 행동들의 효용성을 종합적으로 판단하는 시스템으로 확장합니다.

3.  **`perception.rs` 기능 강화:**
    *   '열려 있는 패스 길을 찾는 기능', '주변의 압박 강도를 감지하는 기능' 등 더 고차원적인 정보를 인지하고 가공하는 기능을 추가합니다.

4.  **`actions/`의 행동 현실성 증진:**
    *   각 행동이 선수의 능력치(`PlayerParams`)에 더 직접적인 영향을 받도록 수정합니다. 예를 들어, `pass_action`은 선수의 `passing` 능력치에 따라 패스 정확도가 달라지도록 만들 수 있습니다.
